# LiteDesk

Windows 10/11 轻量桌面整理工具（C++ / Win32）。桌面右键按需启动、一键整理：非应用项移入**与桌面同卷**的 `X:\LiteDesk\Parked`（`X` 为桌面所在盘），在半透明悬浮窗内左右分栏展示（左文件夹、右文件，可拖分割条）；`.exe` / `.lnk` 等应用项留在桌面。清单与日志在 `%AppData%\LiteDesk`。

## 环境

- Windows 10/11 x64
- Visual Studio 2022（含「使用 C++ 的桌面开发」）
- CMake 3.20+

## 构建

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release
```

产物：

- `build\Release\LiteDesk.exe` — 主程序（GUI / `WIN32`；`comctl32` / `uxtheme` 延迟加载）
- `build\Release\LiteDeskTests.exe` — 控制台单元测试

## 自检（自动化）

```powershell
cmake --build build --config Release --target LiteDeskTests
.\build\Release\LiteDeskTests.exe
```

退出码应为 `0`。

## 用法

1. 首次运行 `LiteDesk.exe` 注册当前用户的桌面右键菜单，然后退出；不显示托盘图标。升级入口可用 `LiteDesk.exe --register`，仅更新菜单，不触碰现有整理数据。
2. 桌面空白处右键选择「一键整理」；Win11 可在「显示更多选项」中找到。菜单启动 `LiteDesk.exe --organize`，整理期间程序保留运行。
3. 自动收纳保持 300ms 防抖。悬浮窗空白处右键可刷新、还原桌面、隐藏；列表支持重命名和 Shell 菜单。可将桌面文件或文件夹多选拖入悬浮窗收纳，也可从窗内多选拖回桌面；拖出项目保持在桌面，直到再次手动整理或刷新，其他新项目照常自动收纳。
   列表支持空白处拉框、Ctrl 点选增减、Shift 连选和 Ctrl+A 全选（作用于当前文件或文件夹列表）；拖动已选项目会移动整组选中项。刷新列表会尽量保留选择和焦点。同名文件不会静默覆盖；拖到文件夹行仍收纳为顶层项目。
4. 隐藏会销毁列表窗口，并短暂交接给干净的后台实例；最终仍只有一个进程，自动收纳继续；再次点桌面右键「一键整理」会重新打开窗口，复用现有会话。
5. 全部还原成功后，程序自动退出。部分项目还原失败时继续显示待还原列表，方便重试。
6. `LiteDesk.exe --restore` 可直接请求还原并退出。程序异常退出后，下次启动先尝试恢复；恢复失败会保留列表。
7. 整理时会冻结桌面重绘、收拢图标空位，并把回收站钉到 FolderView 客户区右下角。
## 数据目录

| 路径 | 说明 |
|------|------|
| `X:\LiteDesk\Parked\` | 整理期间从桌面移入的文件/文件夹（与桌面同盘） |
| `%AppData%\LiteDesk\manifest.json` | 收纳记录（桌面原名 ↔ Parked 路径） |
| `%AppData%\LiteDesk\session.flag` | 整理会话标记；异常退出时下次启动尝试自动还原 |
| `%AppData%\LiteDesk\logs\` | 运行日志 |
| `%AppData%\LiteDesk\ui.ini` | 悬浮窗位置与分割条 |
| `%AppData%\LiteDesk\desktop-kept.json` | 拖回桌面项目的临时身份豁免；隐藏交接保留，手动整理或还原后清除 |

**如何还原桌面**

- 悬浮窗空白菜单 **还原桌面**，成功后自动退出；也可运行 `LiteDesk.exe --restore`。
- 若被强杀/崩溃：再次启动会检测 `session.flag` 并自动还原。
- 还原时桌面已有同名项会加后缀 ` (1)`、` (2)` …，不覆盖。
- 还原失败项留在 `manifest.json`，下次启动或再还原时重试。

## 内存与生命周期

不整理时没有后台进程，常驻专用内存为 0。桌面右键启动后仅保留一个 LiteDesk 进程，同时负责列表和自动收纳。隐藏时短暂启动干净实例接管监视，旧实例退出，随后仍只有一个后台进程；交接失败则旧实例继续工作。进程编号会变化，交接期间新增文件会补扫收纳。全部还原成功后程序退出。

三轮合成桌面对照中，隐藏后的专用内存中位数由约 4.42 MiB 降至 1.42 MiB；继续自动收纳后约 1.58 MiB。本机真实隐藏后实测约 1.64 MiB。具体负载及波动见 [隐藏内存优化验收](docs/hidden-memory-2026-11-01.md)。
## v1 已知限制

- 不注册 Shell 扩展；不支持多屏独立布局、覆盖已有桌面文件。拖入仅接受当前用户桌面直属项目。
- 仅监视当前用户桌面（不含公共桌面）。
- 整理中正在下载/占用的文件可能收纳失败，需等就绪后「刷新」或等监视自动重试。
- **会话内 300ms 自动收纳**：整理后桌面一有变化约 300ms 防抖后自动 park，可能打断「新建后重命名」或浏览器下载。需要时先还原再操作。
- **OneDrive 重定向桌面**：移动会触发同步；「仅在线」占位可能导致失败或变慢。
- **暂存位置**：`Parked` 在桌面所在卷 `LiteDesk\Parked`；无法创建时回退 `%AppData%\LiteDesk\Parked`（跨卷时文件夹仍可能失败）。
- 隐藏/系统属性桌面项与 `desktop.ini` 不会被收纳。

## 手工验收清单

在**测试账户或已备份的桌面**上逐项勾选：

- [ ] **一键整理**：桌面仅剩应用项；悬浮窗左栏文件夹、右栏文件。
- [ ] **还原 / 退出**：还原后程序自动退出、桌面恢复；`Parked\` 为空；无 `session.flag`。
- [ ] **崩溃恢复**：整理后强杀进程，再次启动应自动恢复桌面。
- [ ] **整理中新增项**：已整理状态下新建文件/文件夹，应被自动收纳并进列表。
- [ ] **还原冲突后缀**：桌面已有同名项时，以 ` (1)` 等形式还原且不覆盖。
- [ ] **列表同步**：在悬浮窗用壳菜单删除项后，列表与 manifest 应同步去掉该项。
- [ ] **就地重命名**：慢双击或右键重命名列表项，Parked 与 manifest 一并更新。
