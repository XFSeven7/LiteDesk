# 常驻内存优化实测（2026-11-01）

本次只修改路径数组容量释放和 COM 初始化时机。关闭悬浮窗时以空 vector 交换释放容量；COM 从进程入口移到悬浮窗创建前，并在销毁后配对释放。窗口创建失败路径也释放 COM。

## 测量方法

Windows x64，MSVC Release。同机、同一账户交替运行修改前后版本，各 5 次，以下取中位数。使用进程 WorkingSet64 / PrivateMemorySize64，1 KiB = 1024 字节。两版均保留原有工作集收缩策略，启动或释放后等待 2 秒。

- 首次启动：运行真正的 LiteDesk.exe，采集仅托盘状态，随后经退出菜单消息正常退出。
- 使用后：独立测试程序直接编译本项目的悬浮列表实现，使用 1000 条合成文件路径，连续创建、填充、销毁 3 次后测量。测试包含 COM 与控件生命周期，不包含完整 App、托盘、监视线程；因此它是关闭界面后的对照实验，不能当作完整应用整理后的绝对占用。没有执行整理，也没有移动真实桌面文件。
- APPDATA 环境变量不能隔离本项目的已知文件夹接口；测量实际使用当前账户的目录。未发现会话恢复标记。

## 结果

| 状态 | 指标 | 修改前 KiB | 修改后 KiB | 变化 |
|---|---|---:|---:|---:|
| 首次启动仅托盘 | 专用内存 | 1628 | 1552 | -76（约 4.7%） |
| 首次启动仅托盘 | 工作集 | 156 | 168 | +12 |
| 合成列表关闭后 | 专用内存 | 3756 | 3676 | -80（约 2.1%） |
| 合成列表关闭后 | 工作集 | 216 | 220 | +4 |
| 合成列表关闭后 | 文件路径数组容量 | 1000 项 | 0 项 | 完全释放 |

收益较小。工作集没有下降，不能宣称物理驻留内存降低。数组释放归还分配器后，分配器仍可能保留内存页；COM 清理也不保证卸载所有依赖库。两项修改合并对比，未独立归因各自的节省。

## 验证与本机材料

- Release 构建成功。

- 项目现有 Release 测试退出码 0。测试写用户数据目录，受限运行时因清理目录权限失败，获准使用所需权限后通过。
