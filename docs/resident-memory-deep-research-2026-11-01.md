# 常驻内存深入研究（2026-11-01）

结论：首次启动仅托盘的基线已接近本机精简托盘对照程序；更明显的空间在于避免常驻进程初始化系统文件图标服务。没有将本轮实验改动合入生产代码。

## 1. 冷启动基线

同机 Windows x64、MSVC Release，各版本交替运行 5 次，启动 1.5 秒后测量，取专用内存中位数。生产版本保留原有逻辑；各完整实验构建关闭桌面菜单注册，避免实验路径写入注册表。实验版本与生产版本不是完全相同的启动路径，几十 KiB 的差异不宜作确定归因。

| 第一轮版本 | 专用内存 KiB |
|---|---:|
| 当前生产版本 | 1656 |
| 默认动态运行库实验构建 | 1664 |
| 静态运行库实验构建 | 1632 |
| 极简托盘程序 | 1456 |

极简程序仅隐藏窗口、系统托盘图标、消息循环，未包含数据恢复、路径处理、单实例等功能，使用系统默认图标。它是本机对照，不能当作 Win32 程序理论下限。即使删掉大量业务，冷启动差距也仅约 200 KiB。

第二轮：当前版本 1660 KiB，极简程序 1460 KiB，Segment Heap 1692 KiB，x86 构建 1728 KiB。静态运行库无显著突破，Segment Heap 和 x86 在本机反而更高，不建议据此替换当前构建。

冷启动 4 个线程在极简程序中也存在；当前没有启动桌面监视线程，不能将这些线程归因于 watcher。

原始数据：`build/resident-research/cold-results.csv`、`heap-results.csv`，模块清单为同目录 `*-modules.csv`。DLL 映像大小不等于专用提交或私有驻留量，本报告没有将 DLL 文件大小相加视为节省量。

## 2. 系统图标服务是主要突破口

专项程序直接编译悬浮列表实现，3 个新进程样本；每个进程创建、填充 1000 条合成 txt 路径、销毁列表，反复 30 次。关闭后继续保留进程，进行原有工作集收缩；未移动真实文件，未启动 watcher，也没有调用 Shell 右键菜单。不是完整 App 使用后绝对内存。

图标对照版平衡 SHGetImageList 返回的接口引用；无图标版同时跳过 LoadSysImages 中的 SHGetImageList，以及 FillList 中每项 SHGetFileInfoW。所有路径数组仍按上一轮修改释放容量。

| 第 30 次销毁后 | 专用内存中位数 KiB | GDI 对象 | USER 对象 |
|---|---:|---:|---:|
| 系统图标开启，接口引用配对释放 | 3948 | 41 | 0 |
| 跳过两处系统图标调用 | 2304 | 5 | 0 |

差距 1644 KiB，约 1.61 MiB、41.6%。这是没有窗口后的内存差距，符合常驻优化方向。无图标实验会改变图标显示，不能原样作为功能等价优化发布。

空列表辅助实验：系统图标开启时第 30 次关闭后中位数 3396 KiB；释放图标接口引用后 3384 KiB；跳过图标服务后 1900 KiB。单纯配对 Release 不会释放整套图标服务状态。重复 30 次后的数据基本稳定，没有证据表明每次创建都有明显的线性内存增长。41 个 GDI 对象也不能仅凭数量认定为泄漏，可能属于系统图标缓存。

尝试 HeapSetInformation 的 HeapOptimizeResources 后，未观察到立即明显下降；这是本机短时实验，不能推断所有负载都无效。Segment Heap 的空 UI 辅助实验也未体现收益。

原始数据：`build/resident-research/ui-probe-results.csv`、`filled-ui-results.csv`；专项源码 `probe.cpp`、`float_snapshot.cpp`，构建配置同目录 CMakeLists.txt。当前 probe 源码是最后一轮带填充数据的版本，早期空列表 CSV 是独立历史实验结果。

## 3. 实现方向排序

1. 如可接受通用文件/文件夹图标，提供轻量图标模式，用自有小图标表，避开主进程 SHGetImageList 和 SHGetFileInfoW。改造相对小，但后续打开 Shell 右键菜单仍可能引入 Shell 状态；需覆盖该路径再测。
2. 如需保留当前系统文件图标和右键菜单，优先做临时 UI 子进程原型：托盘与会话管理常驻，列表窗口、系统图标和 Shell 右键在子进程中运行，隐藏/还原后退出子进程。进程退出能清理该进程的图标缓存等状态。首次启动不一定更省，创建时总内存可能更高；价值主要在关闭后的长期空闲。主进程在会话中仍需自动收纳，不能简单退出或停用监视。
3. 另一种保留图标的方案是临时图标提取进程，向主进程传输有限数量的图标像素，主进程使用自有图标表；需要缓存上限、传输协议，且 Shell 菜单仍可能使主进程重新加载相关状态，通常不如整套 UI 分离直接。

本轮没有实现进程拆分，因此不能承诺完整 App 最终能节省 1.61 MiB，也不能将两进程运行时的总开销忽略。应先验证隐藏后、还原后以及打开过右键菜单后三种长时空闲状态，并统计进程树总专用内存、交互延迟和稳定性。

- [运行库选择 /MD 与 /MT](https://learn.microsoft.com/en-us/cpp/build/reference/md-mt-ld-use-run-time-library)：动态与静态运行库构建的区别。
