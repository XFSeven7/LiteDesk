# UI 子进程实现与常驻内存验收（2026-11-01）

已实现同一 exe 的临时 UI 模式：托盘、监视、整理、还原及清单写入留在主进程；悬浮列表、系统图标与 Shell 菜单在 worker 中执行。隐藏后 worker 退出，整理会话中的自动收纳继续运行。还原时先关闭 worker，再恢复文件；失败项目可重新打开列表。主进程退出或崩溃时，Job 自动清理 worker；用户从列表打开的外部应用允许脱离 Job，不随列表关闭。

## 生命周期与数据一致性

- worker 模式在单实例检查前分流，仅接受匹配父窗口及父进程的启动参数。
- 有上限的启动握手和退出等待；退出等待仍接收同步消息，避免重命名与关闭互等。
- 主进程按当前 worker 窗口和 PID 校验消息；隐藏等待父进程确认，不丢最后的清理通知。
- 重命名经 WM_COPYDATA 交给主进程；校验消息长度、两段字符串、清单成员资格后执行。
- UI 只读清单。清单读取允许删除共享，并以短时间的命名互斥锁保护读取/原子替换。读锁或解析失败时，已有清单不能被当成空记录继续整理。
- 性能测试显式等待列表刷新完成，避免把消息投递时间误报为显示内容时间。

## 内存对照

Windows x64 / MSVC Release，同机五轮交替运行，各取中位数。使用同一个安全测量程序执行真实 App 的 Init、Organize、隐藏、Restore、Shutdown；每轮使用 1000 个合成 txt 文件，反复创建/关闭列表三次，采样前消息循环空闲 1.5 秒。

测试构建仅把桌面和应用数据重定向到工作区，并关闭真实桌面图标排列和菜单注册。没有整理真实桌面。对照基线是此前已完成 COM 延迟初始化和数组容量释放的版本；两边采用相同当前清单读写实现。这里是控制条件下的完整 App 行为对照，不等同于用户真实桌面的绝对占用。

| 状态 | 迁移前专用 KiB | 迁移后主进程 KiB | 迁移后进程树合计 KiB |
|---|---:|---:|---:|
| 首次启动空闲 | 1764 | 1760 | 1760 |
| 列表打开 | 4768 | 2416 | 6820 |
| 隐藏后继续监视 | 4472 | 2416 | 2416 |
| 还原后空闲 | 4204 | 2132 | 2132 |

隐藏后减少 2056 KiB（约 46%），还原后减少 2072 KiB（约 49%）。两种常驻状态下 worker 数量均为 0。列表打开时合计增加 2052 KiB（约 43%），是临时第二进程的代价。首次启动没有明显收益。

五轮数据对应最终安全保护和测试隔离收尾之前的候选版；收尾后另做最终版本单轮复核。原始 CSV 位于 `build/ui-memory-compare/results.csv`；最终复核输出见同目录 `final-check.txt`。可重复测量程序源码位于 `tests/memory_probe.cpp`，目标 LiteDeskMemoryProbe 按需构建；候选基线源码与构建配置保留在本机 build 目录。

## 验证

- Release 主程序及所有测试目标构建成功。
- LiteDeskUiTests：重复启动不重复创建、关闭、worker 崩溃重建、父进程强制终止后无孤儿。
- LiteDeskSessionTests：在合成桌面验证异常会话恢复、应用项保留、整理、跨进程重命名、无效发送者拒绝、删除后清单修剪、隐藏后的自动收纳、worker 崩溃重建、还原与退出恢复；主进程始终未加载 comctl32。
- LiteDeskManifestTests：1000 项清单、300 次写入与并发读取。修复前复现 203 次写失败与 67 次读失败；修复后读写失败均为 0。
- 原有 LiteDeskTests 通过，新增已有清单读取失败时禁止移动文件或覆盖记录的回归检查。原有测试需访问用户数据目录中的测试文件夹。
- 无真实桌面的交互式 Shell 扩展菜单手工验收，也未验证所有第三方 Shell 扩展；原有菜单实现保留在 worker 中。
