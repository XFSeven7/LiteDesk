# 按需运行验收（2026-11-01）

程序取消所有托盘图标、托盘菜单及气泡通知。无参数启动注册桌面菜单并处理异常恢复，完成后退出。右键菜单命令仍为引号包裹的 exe 路径加 --organize；整理会话持续运行，包括隐藏窗口后的自动收纳。还原成功后退出所有主/子进程；失败时保留项目列表供重试。

新增 --register 仅更新菜单入口，不初始化 App、恢复文件或启动监视；本机两个 HKCU 菜单入口均已更新为 `build/on-demand/Release/LiteDesk.exe --organize`，并回读验证。注册不重启 Explorer，也不强制改变 Windows 全局右键菜单样式。Win11 普通动词在完整右键菜单可见。

单实例转发改为等待启动窗口并确认命令被接受。还原中返回忙状态，退出中拒绝新命令；客户端可重试转发，或等待旧进程释放单实例锁后接管。恢复和退出在等待 worker 期间不允许重入整理。

## 验证

- Release 构建通过；新产物：`build/on-demand/Release/LiteDesk.exe`。
- LiteDeskCommandTests：同一入口代码在合成桌面中执行子进程测试。无参数不驻留、--organize 启动、隐藏后不退出且继续自动收纳、再次 --organize 转发并重开窗口、还原后父子进程退出、无现有实例的 --restore、--register 不恢复已有文件、锁定文件导致恢复失败时保持界面，释放后还原并退出。退出码 0。
- 修改前新命令测试确定性失败于无参数启动无法退出；修改后通过。
- LiteDeskSessionTests：此前会话场景回归通过；新增确定性并发检查：暂停 worker，让主进程在等待其退出期间收到同步 organize 请求，确认返回忙状态而非确认接受。测试仅暂停测试进程，随后恢复它。
- LiteDeskUiTests：UI 生命周期及无孤儿检查通过。
- LiteDeskManifestTests：并发读取和 300 次写入，失败数均为 0。
- 原有 LiteDeskTests：退出码 0；使用其原有用户数据测试目录，需要相应权限。
- 导入表和源码检查：不再包含 Shell_NotifyIcon 托盘调用。
- 本机实际执行新版本 --register，退出码 0，两个注册表命令均回读为新路径。

本轮没有运行真实桌面的一键整理或还原。正常未整理及还原成功后无进程存活，因此该程序在这些阶段不占常驻专用内存；整理/隐藏监视期间仍有必要的主进程占用。

## 默认启动文件同步修复

后续排查发现：HKCU/HKCR 的菜单命令已经指向新版，但 Explorer 实际仍启动 `build/Release/LiteDesk.exe --organize`；默认路径上的文件还是旧托盘版本。此前仅更新菜单和独立输出目录不足以覆盖这个入口。

已正常退出旧会话并还原文件，备份旧二进制后，将 `build/Release/LiteDesk.exe` 和 `build/ui-worker/Release/LiteDesk.exe` 同步为已测试的按需版本；菜单重新注册到标准 `build/Release` 路径。三个路径 SHA256 均为 `60DA6C1D13D15C1F9CCADD057A9A0FFB9EB46EDEA1359D421DF5E40E3C7D7FA2`。默认 exe 的导入表不含 Shell_NotifyIcon。

随后恢复当前整理会话，并在独立检查中确认新版主进程和 UI worker 持续运行；再次执行 --organize 返回 0、复用同一个主进程，未再启动旧版本。
